Performance was 100 on both production runs, 100 on local desktop, and 97 on local mobile. `python3 -m http.server` sends the HTML and `hypersig.js` uncompressed where Vercel compresses them, which likely explains the local mobile LCP (not verified).

A run from the owner's own Chrome scored 89, with Speed Index at 5.4 s. In that run the HTML took 9.1 s to finish arriving while the server answered in 27 ms, and Lighthouse warned that extensions slowed the load and that clearing the cache timed out, so the loss came from that browser and not from the site.

## `/`
- **Performance · unsized-images**: `/pencil.svg` had no `width` and `height` · impact low (CLS 0.0002 in the owner's run) · fix: set them to the SVG's own size, 816×144
- **Performance · lcp-discovery-insight**: `/pencil.svg` is the LCP element and had no `fetchpriority` · impact low · fix: `fetchpriority="high"`
- **Performance · unused-javascript**: 89% of `hypersig.js` (21 KB of 24 KB) is unused on load · impact none on the metrics (TBT 0 ms) · not fixed: the page loads the hypersig runtime by design
- **LCP**: element `/pencil.svg`, TTFB 198 ms, resource load delay 33 ms, resource load 26 ms, render delay 38 ms (production, desktop)
- **CLS**: the header shifted 0.001 on production mobile, as the font arrived
- **Render-blocking**: none

## After the fix
`/pencil.svg` now carries `width="816" height="144" fetchpriority="high"`. On `http://localhost:8000/`, `unsized-images` and `lcp-discovery-insight` pass. Desktop stays at Performance 100 with LCP 600 ms and CLS 0, and mobile reads Performance 96 with LCP 2700 ms and CLS 0.001, within run-to-run noise of the measurement before the fix.
